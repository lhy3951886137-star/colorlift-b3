# ColorLift Studio

用于三色方块抓取实验的网页工作台。二维布置场景，三维预览机械臂，选择目标颜色并启动实时演示。默认不加载模型，所有演示动画均明确标记 DEMO。

## 启动

推荐 Node.js 22 或24。Windows 双击 `启动网站.cmd`，然后打开 http://localhost:4173 。保持终端窗口开启。

也可在此目录执行：

```powershell
npm.cmd install
npm.cmd start
```

运行 `npm.cmd test` 检查几何碰撞、场景验证及 robosuite 布局映射。运行时不依赖 CDN、在线字体或外部素材。Three.js 从本地依赖提供。

## 使用

1. 默认提供三个方块的示例布局，可点击“清空”重新摆放。
2. 点击右上角某种颜色的方块，把鼠标移动到二维桌面，左键固定中心。每种颜色一个，与现有三方块策略匹配。
3. 单击已放置方块可选中；拖动移动；沿灰色弧线或圆形旋转柄拖动可旋转。属性面板也可输入 X/Y（mm）和调整角度。
4. 旋转后的真实轮廓进行多边形相交检测。交叠部分红色斜线+禁止图标；无效新方块不能放置；无效移动/旋转在松开时恢复。
5. 方块中心限制在 X/Y ±145 mm，方块边长40 mm。虚线框表示中心位置支持范围，方块外缘可越出虚线框；实际桌面0.8 m，不会越出桌面。此为编辑合法性限制，不保证所有场景都适合现有策略。
6. 选择抓取目标后点击运行，切换三维并通过 SSE 接收实时阶段/状态。默认演示不计算真实成功率。
7. 三维画面拖动旋转、滚轮缩放、右键平移；可选透视/正面/俯视。
8. 导出和导入场景 JSON，可重复比较模型表现；三方块完整布局会自动本地保存。
9. Esc取消摆放，Delete/Backspace删除选中方块，Ctrl/⌘+Z撤销。

## 运行记录

每次点击运行会生成记录，保存初始布局、目标颜色、演示/模型来源、阶段切换步数、执行步数、接收状态中的最大抬升与最长保持、实际经过时间和最终结果。页面下方或左侧“记录”可查看，支持筛选来源、查看详情、恢复初始布局、导出单次或全部JSON。

记录保存在当前浏览器localStorage，最多保留最近30次；清理浏览器数据会移除，重要记录请导出。存储不可用时会显示提示，并暂存在当前页面。刷新时未终止的记录标记“页面中断”，不能据此断定后端任务是否停止。记录不包含视频或模型权重。

模型成功率只计算后端明确判为成功或失败、且正常完成/失败的模型任务；演示完成、手动停止、页面中断、连接错误和未判分任务单独保留。完成步数及平均完成步数仅统计模型明确成功回合。此统计范围仅为浏览器保留的30条记录，不能替代固定测试集完整评测。演示动画的高度、保持和步数均不代表真实模型性能。

## 与真实环境的关系

- 坐标沿用 robosuite 世界坐标，以桌面中心为X/Y原点，单位米，yaw弧度；渲染器转换为 Three.js 的Y向上坐标。
- 桌面高度0.8 m、方块尺寸0.04 m、现有成功判据“相对初始高度抬升超过4 cm并稳定保持2秒”。
- 当前三维机械臂是程序绘制的 Panda 风格预览，并非 robosuite 实时仿真、官方精确机器人网格或训练策略输出。演示采用插值轨迹，没有物理接触求解。
- 真实环境还会检查接触、速度、漂移、抓错颜色等条件；网页不自行替代后端判分。
- 任意手工布局可能超出模型训练分布。编辑器只验证中心范围和方块重叠，没有沿用训练数据的近邻距离、保留区域、IK/可见性筛选。模型后端应明确验证可执行性并返回错误，不应静默移动物体。

## 接模型

已实现本机 B3 模型服务 `backend/robot_service.py`，复用 Ubuntu 项目 `/home/banus/colorlift-b3` 的冻结 seed44 权重。双击 **启动模型网站.cmd**，等待模型就绪后访问 **http://localhost:4180**。原演示入口4173可单独运行。

要求 WSL发行版Ubuntu-22.04、已安装的项目虚拟环境 `.venv/bin/python`、现有模型与NVIDIA CUDA/EGL。启动时验证发布清单中的权重SHA256。模型服务仅监听本机8000，网站仅监听本机4180；没有公网部署或模型上传。

模型服务保持权重常驻，所有CUDA/EGL和仿真工作在同一线程，最多一项任务。B3控制循环保留双相机128×128输入、原归一化、颜色embedding、4/2/1/4查询与原EventExecutor。运行面板另有“方向示范”控制器：使用仿真物块位置决定腕部朝向，在高处先旋转、再下降，使用真实robosuite相机和原碰撞/接触判据。方向示范允许方块边缘相接但仍拒绝几何重叠；原B3模式仍要求方块之间留出间隙。此模式是有特权信息的规则教师，不代表B3策略，单独记录且不计入B3成功率。展示相机另以640×480渲染，不改变策略输入。任意网页布局可能超出训练分布，不能保证抓取成功；后端验证布局静置稳定性，不会静默移动物块。

停止按钮会等待仿真退出并收到最终取消事件，取消不计成功/失败。模型服务异常、通信错误也不伪报抓取失败。结果来自原环境稳定接触、速度、漂移、连续2秒和正确目标判据。contact-qualified为额外诊断，独立于任务成功率。

每项运行保存至 `机器人项目/results/web_model_runs/<run_id>/`：`request.json`（输入布局、权重/代码摘要）、`initial_state.json`、`initial_front.png`、`frames.jsonl`（不含图像base64）、`steps.csv`、`front.mp4`和`result.json`。在网页记录详情可回看视频。在线视频链接只在模型服务保留该运行时可用；硬盘文件不会因服务重启删除。

当前接的是已下载的B3发布权重。以后换你们的新模型时，需要对应架构、输入和动作执行配置。协议见 `API.md`。也可手动连接另一个后端：

```powershell
$env:ROBOT_BACKEND_URL = 'http://127.0.0.1:8000'
npm.cmd start
```

后端应在 Python/WSL 中加载模型、按用户布局 reset robosuite、执行策略，并通过 SSE 返回状态和相机图像。将 RGB 编码为 JPEG data URL 放在 `frame.image`，即可直接在网站中显示真正的仿真运行画面。网站已具备该展示路径。

## 文件

- `server.mjs`：静态服务器、场景验证、演示状态流、模型服务代理。
- `public/app.js`：编辑交互、历史撤销、导入导出、运行生命周期。
- `public/geometry.js`：前后端共享的旋转几何检测、坐标映射。
- `public/world.js`：Three.js 三维场景与机械臂动画。
- `API.md`：后续 Python 模型后端的接入约定。

默认仅监听 `127.0.0.1:4173`，供本机使用。正式公开部署时再配置认证、访问控制、任务队列、HTTPS和GPU资源管理。

公网演示版部署操作见 `DEPLOY.md`。生产环境使用 `NODE_ENV=production` 或设置 `HOST=0.0.0.0`，端口读取平台的 `PORT` 环境变量。`GET /api/health` 用于平台健康检查。
